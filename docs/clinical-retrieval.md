# Clinical retrieval: build, inspect, rebuild

Developer notes for the local Toronto Notes index, the typed clinical contrast graph, hybrid
retrieval and difficulty intent. Design: `docs/superpowers/specs/2026-09-04-mccqe-clinical-contrast-graph-rag-and-difficulty-design.md`.

## What is tracked and what is not

| Local, gitignored | Tracked |
|---|---|
| `derived/tn_index/tn_index.sqlite3` — the index and graph database, ~37 MB, contains corpus text | code, tests, schemas |
| `derived/toronto-notes-2025/` — OCR pages and clean text | `research/tn2025/tn_index_build_manifest.json` (counts, hashes, tokenizer) |
| | `research/qgen/safe_yield/retrieval_benchmark_reference.json` |
| | `reports/qgen_clinical_retrieval_*.json` and `.md` |

The database is never committed. It is rebuilt from canonical local artifacts in about 3 seconds, so
committing it would trade a 37 MB copyright-sensitive blob for nothing. The copyright audit asserts
this: `reports/qgen_clinical_retrieval_copyright_audit.json`.

## Rebuild

```bash
.venv/bin/python -m qbank build-tn-index && .venv/bin/python -m qbank build-clinical-graph
```

`build-tn-index` reads `derived/toronto-notes-2025/ocr/`, `research/tn2025/toc_inventory.json` and
`research/scope/master_scope_crosswalk.json`, and writes the database plus the tracked build manifest.
`build-clinical-graph` drops and reprojects every graph table in that same database, so it is safe to
re-run and is the way to clear graph caches. To clear everything, delete `derived/tn_index/` and run
both commands again.

## Run the benchmark

```bash
.venv/bin/python -m qbank run-retrieval-benchmark
```

Runs all four arms over the 30 frozen G2 opportunities and rewrites
`reports/qgen_clinical_retrieval_benchmark.json`. The frozen reference set and the pass rule are
**not** regenerated by this command; they live in `research/qgen/safe_yield/retrieval_benchmark_reference.json`
and are reproduced from their frozen inputs by a test. If that test fails, a frozen input changed and
the benchmark is no longer comparable to its recorded result.

## Inspect retrieval provenance

Every candidate carries the path that produced it. From Python:

```python
import sqlite3
from pathlib import Path
from qbank.clinical_retrieval import retrieve_competitors, build_context_packet
from qbank.retrieval_benchmark import load_scenarios

scenario = {s["wave_label"]: s for s in load_scenarios(Path("."))}["G2-MED-01"]
connection = sqlite3.connect("derived/tn_index/tn_index.sqlite3")
result = retrieve_competitors(connection, scenario, arm="GRAPH", root=Path("."))

for competitor in result["retrieval"]["ranked_competitors"]:
    print(competitor["seed_id"], competitor["anchors_present"], "/", competitor["total_anchors"])
    for path in competitor["retrieval_provenance"]["graph_paths"]:
        print("   ", " -> ".join(f'{s["relation"]}({s["edge_id"]})' for s in path))
print(result["retrieval"]["excluded"])          # why each candidate was refused
print(build_context_packet(connection, scenario, result)["size"])
```

`excluded` names the rule that removed each candidate: `ADM_1` response class, `ADM_3` second-key
ceiling, `SAF_1` stem-anchor floor.

## Source authority

Two roles, and the separation is enforced rather than documented.

- `TOPIC_DISCOVERY_SOURCE` — Toronto Notes. Supplies vocabulary, differentials, page provenance and
  `CONFUSED_WITH` candidates. It may **propose** a competitor.
- `CURRENT_CLINICAL_AUTHORITY` — an MCC, Canadian-guideline or peer-reviewed source with a
  currentness date. Only these may **justify** a candidate-facing clinical claim.

`clinical_graph.edges_eligible_to_justify()` returns only the second kind, and a test asserts no
Toronto Notes edge ever appears in it. `classify_source_authority` maps a packet source onto the
coarse class from its declared `source_type`, falling back to the issuing organization for older
packet schemas; anything unresolved is `OTHER` and never justifies.

Claim status is stored as `transcription_status`, not `verification_status`, because
`VERIFIED_COMPLETE` in the evidence packets asserts that a transcription was checked — not that the
statement is true. Reading it as truth has already produced two defects in this repository.

## Adding concept aliases safely

Aliases come from three rules and nothing else: `EXACT`, `PLURAL_S`, `HYPHEN_FOLDED`
(`clinical_concepts.build_alias_index`). Normalization folds case, punctuation and spacing only.

Do not add stemming or synonym folding to `normalize_surface_form`. It would merge hyperkalemia with
hypokalemia and hypertonic with hypotonic saline; both are pinned by tests. To add a genuine alias,
add it to the vocabulary source artifact, not to the normalizer. A surface form owned by two concepts
resolves to `MULTI_MATCH` and is never silently assigned to one of them.

## Difficulty intent

`qbank.question_difficulty`. `DIFFICULTY_INTENT` (EASY / MEDIUM / HARD) is authored and available at
generation time. `EMPIRICAL_DIFFICULTY` and the other measured fields live in a separate record and
are null until learners answer; neither record may carry the other's fields.

`classify_difficulty` requires a rationale and refuses one resting on any of the nine prohibited
difficulty sources — stem length, option count, rarity, obscure vocabulary, withheld information,
trick wording, board-level knowledge, padded distractors, deliberate ambiguity. A difficulty target
that cannot be met from admissible competitors fails closed; it never degrades the option set to
reach the target.

The 20 / 55 / 25 library mix is `INITIAL_LEARNING_DESIGN_POLICY`. The MCC publishes no categorical
difficulty bands and no target proportions, and nothing here may be cited as evidence about the real
examination.

## What this subsystem is not wired into

Nothing. Question generation is unchanged: `safe_yield_wave`, `question_opportunity` and
`profile_contrast_retrieval` were not modified, and `profile_contrast_retrieval` in particular is
benchmark arm A and must stay that way for the recorded baseline to mean anything. Integrating
retrieval into generation is a separate, user-gated decision.
